> **TL;DR** — Build `safe`, a real-time user safety gateway that inspects posts, comments, and messages for toxicity, PII leaks, and abuse patterns before they reach other users. It combines a FastAPI serving layer, a multi-stage scoring pipeline, Redis-based rate limiting, and a configurable policy engine — the kind of system that demonstrates distributed systems thinking, ML integration, and production-grade engineering on a single CV line item.

You do not need a billion-dollar platform to demonstrate systems thinking on a CV. What you need is a project that forces you to make the same architectural decisions real platforms make: where to draw the latency budget, how to degrade gracefully, what to log for post-hoc audit, and how to let policy change without a code deploy. `safe` is a hands-on build that asks exactly those questions.

## Architecture Overview

`safe` is structured as a layered pipeline. Content enters through the API, passes through independent detection stages, accumulates a safety score, and exits through a policy engine that decides the action. Each layer is decoupled so it can be scaled, replaced, or observed independently.

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  User Input  │────▶│  API Gateway  │────▶│  Policy Engine   │
│  (POST /scan)│     │  (FastAPI)    │     │  (Config-driven) │
└─────────────┘     └──────────────┘     └────────┬────────┘
                                                   │
                                    ┌────────────────┼────────────────┐
                                    ▼                ▼                ▼
                            ┌────────────┐  ┌──────────────┐  ┌──────────────┐
                            │ Toxicity   │  │ PII Detector │  │ Abuse/Rate   │
                            │ Scorer     │  │              │  │ Limiter      │
                            │ (Model)    │  │ (Regex +     │  │ (Redis)      │
                            │            │  │  LLM fallback)│  │              │
                            └─────┬──────┘  └──────┬───────┘  └──────┬───────┘
                                  │                │                │
                                  ▼                ▼                ▼
                            ┌─────────────────────────────────────────────┐
                            │         Score Aggregator & Decision        │
                            │    (weighted sum → action: ALLOW/FLAG/BLOCK)│
                            └──────────────────┬────────────────────────┘
                                               │
                                    ┌────────────┴────────────┐
                                    ▼                         ▼
                            ┌────────────┐            ┌──────────────┐
                            │  Audit Log │            │  Response    │
                            │ (Postgres) │            │  to Client   │
                            └────────────┘            └──────────────┘
```

**Components in bullet form:**

- **API Gateway (FastAPI)** — Receives content payloads, validates input schema, attaches a request ID for tracing, and forwards to the pipeline. Stateless and horizontally scalable.
- **Policy Engine** — A YAML-configured ruleset that defines thresholds per category (toxicity score > 0.8 → BLOCK, PII detected → FLAG, etc.). Changing a threshold is a config change, not a deploy.
- **Toxicity Scorer** — A transformer-based model (e.g., `unitary/toxic-bert` or `facebook/roberta-hate-speech-detect`) served behind a gRPC or HTTP wrapper. Returns a probability distribution over categories: toxic, severe_toxic, obscene, threat, insult, identity_hate.
- **PII Detector** — A regex-based first pass for high-confidence patterns (credit card numbers, SSNs, emails), with an LLM fallback for ambiguous cases. The two-stage design keeps latency low for the obvious cases.
- **Abuse/Rate Limiter** — Redis-backed sliding-window counter that tracks request volume per user/IP. Prevents a single bad actor from flooding the system.
- **Score Aggregator** — Combines per-stage scores using configurable weights, applies the policy engine's thresholds, and produces a final action.
- **Audit Log (PostgreSQL)** — Every decision is persisted with the input hash, scores, applied policy version, timestamp, and the actor who triggered the evaluation. This is non-negotiable for any system that touches user safety.
- **Response to Client** — Returns the action, a confidence score, and a breakdown of which rules fired. Transparency here is a trust-and-safety best practice.

The critical architectural insight is that **no single detector owns the final decision**. The policy engine is the only component that maps scores to actions. This separation lets you swap detectors without touching business logic, and update policy without touching code.

### Step 2: Define the policy engine

The policy engine is the brain. It reads a YAML config and maps scores to actions.

```yaml
# config.yaml
policy_version: "1.2.0"

thresholds:
  block:
    toxicity: 0.80
    pii_detected: true
    rate_limited: true
  flag:
    toxicity: 0.50
    pii_detected: false

weights:
  toxicity: 0.6
  pii: 0.25
  abuse_score: 0.15

actions:
  ALLOW: "content_passes"
  FLAG: "content_review_required"
  BLOCK: "content_rejected"
```

```python
# policy/engine.py
import yaml
from dataclasses import dataclass
from typing import Literal

@dataclass
class PolicyConfig:
    version: str
    thresholds: dict
    weights: dict
    actions: dict

class PolicyEngine:
    def __init__(self, config_path: str = "config.yaml"):
        with open(config_path) as f:
            raw = yaml.safe_load(f)
        self.version = raw["policy_version"]
        self.thresholds = raw["thresholds"]
        self.weights = raw["weights"]
        self.actions = raw["actions"]

    def decide(self, scores: dict) -> tuple[Literal["ALLOW", "FLAG", "BLOCK"], str, float]:
        """
        Evaluate scores against policy thresholds and return the action.
        Returns (action, reason, confidence).
        """
        toxicity = scores.get("toxicity", 0.0)
        pii_detected = scores.get("pii_detected", False)
        abuse_score = scores.get("abuse_score", 0.0)

        # Block conditions
        if (toxicity >= self.thresholds["block"]["toxicity"] or
            pii_detected or
            abuse_score >= self.thresholds["block"]["rate_limited"]):
            reasons = []
            if toxicity >= self.thresholds["block"]["toxicity"]:
                reasons.append(f"toxicity={toxicity:.2f} >= {self.thresholds['block']['toxicity']}")
            if pii_detected:
                reasons.append("PII detected")
            return ("BLOCK", "; ".join(reasons), 1.0)

        # Flag conditions
        if toxicity >= self.thresholds["flag"]["toxicity"]:
            return ("FLAG", f"toxicity={toxicity:.2f} >= {self.thresholds['flag']['toxicity']}", toxicity)

        return ("ALLOW", "content_within_policy", 1.0)
```

### Step 3: Build the toxicity scorer

```python
# pipeline/scorer.py
from transformers import pipeline
from typing import Dict
import logging

logger = logging.getLogger(__name__)

class ToxicityScorer:
    def __init__(self, model_name: str = "unitary/toxic-bert"):
        self.classifier = pipeline(
            "text-classification",
            model=model_name,
            top_k=None,
            truncation=True,
            max_length=512
        )
        self.category_map = {
            "toxic": "toxicity",
            "severe_toxic": "severe_toxicity",
            "obscene": "obscenity",
            "threat": "threat",
            "insult": "insult",
            "identity_hate": "identity_hate"
        }

    def score(self, text: str) -> Dict[str, float]:
        try:
            results = self.classifier(text)[0]
            scores = {}
            for result in results:
                label = result["label"].lower()
                if label in self.category_map:
                    scores[self.category_map[label]] = result["score"]
            # Return the maximum toxicity score as the primary signal
            primary = max(scores.values()) if scores else 0.0
            scores["toxicity"] = primary
            return scores
        except Exception as e:
            logger.error(f"Toxicity scoring failed: {e}")
            # Graceful degradation: return neutral score
            return {"toxicity": 0.0, "severe_toxicity": 0.0}
```

### Step 4: Build the PII detector

```python
# pipeline/pii_detector.py
import re
from typing import Dict, List

class PIIDetector:
    def __init__(self):
        self.patterns: List[re.Pattern] = [
            re.compile(r'\b\d{3}-\d{2}-\d{4}\b'),        # SSN
            re.compile(r'\b\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}\b'),  # Credit card
            re.compile(r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b'),  # Email
            re.compile(r'\b\d{3}-\d{3}-\d{4}\b'),         # Phone
        ]

    def detect(self, text: str) -> Dict[str, bool]:
        matches = []
        for pattern in self.patterns:
            if pattern.search(text):
                matches.append(pattern.pattern[:20])

        return {
            "pii_detected": len(matches) > 0,
            "pii_types": matches,
            "pii_count": len(matches)
        }
```

### Step 5: Build the rate limiter using Redis

```python
# pipeline/rate_limiter.py
import redis
import time
from typing import Dict

class RateLimiter:
    def __init__(self, redis_client: redis.Redis, max_requests: int = 20, window_seconds: int = 60):
        self.redis = redis_client
        self.max_requests = max_requests
        self.window_seconds = window_seconds

    def check(self, identifier: str) -> Dict[str, bool]:
        """
        Sliding-window rate limit. Returns whether the request is allowed
        and the current count.
        """
        key = f"rate_limit:{identifier}"
        now = time.time()
        pipeline = self.redis.pipeline()

        # Remove expired entries
        pipeline.zremrangebyscore(key, 0, now - self.window_seconds)
        # Add current request
        pipeline.zadd(key, {str(now): now})
        # Get current count
        pipeline.zcard(key)
        # Set expiry on the key
        pipeline.expire(key, self.window_seconds)

        _, _, count, _ = pipeline.execute()

        return {
            "rate_limited": count >= self.max_requests,
            "current_count": count,
            "max_requests": self.max_requests
        }
```

### Step 6: Build the score aggregator

```python
# pipeline/aggregator.py
from typing import Dict, Any

class ScoreAggregator:
    def __init__(self, weights: Dict[str, float]):
        self.weights = weights

    def aggregate(self, toxicity_scores: Dict[str, float],
                  pii_result: Dict[str, bool],
                  rate_result: Dict[str, bool]) -> Dict[str, Any]:
        toxicity = toxicity_scores.get("toxicity", 0.0)
        pii_score = 1.0 if pii_result.get("pii_detected") else 0.0
        abuse_score = 1.0 if rate_result.get("rate_limited") else 0.0

        weighted = (
            self.weights["toxicity"] * toxicity +
            self.weights["pii"] * pii_score +
            self.weights["abuse_score"] * abuse_score
        )

        return {
            "toxicity": toxicity,
            "pii_detected": pii_result.get("pii_detected", False),
            "rate_limited": rate_result.get("rate_limited", False),
            "abuse_score": abuse_score,
            "composite_score": round(weighted, 4),
            "pii_types": pii_result.get("pii_types", [])
        }
```

### Step 7: Wire it all in the FastAPI application

```python
# api/main.py
import uuid
import logging
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from pipeline.scorer import ToxicityScorer
from pipeline.pii_detector import PIIDetector
from pipeline.rate_limiter import RateLimiter
from pipeline.aggregator import ScoreAggregator
from policy.engine import PolicyEngine
from storage.audit import AuditStore
import redis

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

app = FastAPI(title="safe — User Safety Gateway")

# Initialize components
redis_client = redis.Redis(host="localhost", port=6379, db=0)
scorer = ToxicityScorer()
pii_detector = PIIDetector()
rate_limiter = RateLimiter(redis_client, max_requests=20, window_seconds=60)
engine = PolicyEngine("config.yaml")
audit = AuditStore()
aggregator = ScoreAggregator(engine.weights)

class ContentPayload(BaseModel):
    text: str
    user_id: str
    content_type: str = "post"

class SafetyResponse(BaseModel):
    request_id: str
    action: str
    reason: str
    confidence: float
    scores: dict
    policy_version: str

@app.post("/scan", response_model=SafetyResponse)
async def scan_content(payload: ContentPayload):
    request_id = str(uuid.uuid4())
    logger.info(f"[{request_id}] Scanning content from user={payload.user_id}")

    # 1. Rate limiting check
    rate_result = rate_limiter.check(payload.user_id)
    if rate_result["rate_limited"]:
        logger.warning(f"[{request_id}] Rate limit exceeded for user={payload.user_id}")
        await audit.log(request_id, payload, "BLOCK", "rate_limit_exceeded", rate_result)
        return SafetyResponse(
            request_id=request_id, action="BLOCK",
            reason="Rate limit exceeded", confidence=1.0,
            scores={"rate_limited": True}, policy_version=engine.version
        )

    # 2. Toxicity scoring
    toxicity_scores = scorer.score(payload.text)

    # 3. PII detection
    pii_result = pii_detector.detect(payload.text)

    # 4. Aggregate scores
    scores = aggregator.aggregate(toxicity_scores, pii_result, rate_result)

    # 5. Policy decision
    action, reason, confidence = engine.decide(scores)

    logger.info(f"[{request_id}] Action={action} reason={reason} confidence={confidence}")

    # 6. Audit log
    await audit.log(request_id, payload, action, reason, scores)

    return SafetyResponse(
        request_id=request_id,
        action=action,
        reason=reason,
        confidence=confidence,
        scores=scores,
        policy_version=engine.version
    )

@app.get("/health")
async def health():
    return {"status": "healthy", "service": "safe"}
```

### Step 8: Persist audit logs to PostgreSQL

```python
# storage/audit.py
import asyncpg
from typing import Dict, Any
import logging

logger = logging.getLogger(__name__)

class AuditStore:
    def __init__(self, dsn: str = "postgresql://localhost/safe_audit"):
        self.dsn = dsn

    async def log(self, request_id: str, payload: Any, action: str,
                  reason: str, scores: Dict[str, Any]):
        try:
            conn = await asyncpg.connect(self.dsn)
            await conn.execute(
                """
                INSERT INTO safety_decisions
                (request_id, user_id, content, content_type, action, reason,
                 scores, policy_version, created_at)
                VALUES ($1, $2, $3, $4, $5, $6, $7, $8, NOW())
                """,
                request_id, payload.user_id, payload.text, payload.content_type,
                action, reason, str(scores), "1.2.0"
            )
            await conn.close()
        except Exception as e:
            logger.error(f"Audit log failed for {request_id}: {e}")

    async def init_db(self):
        conn = await asyncpg.connect(self.dsn)
        await conn.execute("""
            CREATE TABLE IF NOT EXISTS safety_decisions (
                id SERIAL PRIMARY KEY,
                request_id VARCHAR(36) UNIQUE NOT NULL,
                user_id VARCHAR(255) NOT NULL,
                content TEXT NOT NULL,
                content_type VARCHAR(50),
                action VARCHAR(10) NOT NULL,
                reason TEXT,
                scores JSONB,
                policy_version VARCHAR(20),
                created_at TIMESTAMP DEFAULT NOW()
            );
            CREATE INDEX IF NOT EXISTS idx_decisions_user
                ON safety_decisions(user_id, created_at);
            CREATE INDEX IF NOT EXISTS idx_decisions_action
                ON safety_decisions(action, created_at);
        """)
        await conn.close()
```

## Extending It: Your Roadmap to Senior-Level

The base project demonstrates real systems skill. But to make it genuinely senior-level on a CV, you need to evolve it. Here are six concrete upgrades, each with a one-line reason it matters:

1. **Add message queue decoupling with Celery or Kafka.** Replace the synchronous pipeline with an async producer-consumer pattern where the API enqueues content and workers process it independently. *This matters because it demonstrates you understand backpressure, decoupling, and how to handle variable processing times without blocking requests.*

2. **Implement horizontal scaling with Kubernetes. Containerize the API, scorer, and PII detector as separate services, deploy behind a load balancer, and use a shared Redis and Postgres layer.** *This matters because it proves you can decompose a monolith into independently scalable microservices — the single most-requested architecture skill in backend hiring.*

3. **Add Prometheus + Grafana observability.** Instrument every pipeline stage with metrics: request latency histograms, per-category score distributions, rate limit hit counts, and model inference times. Set alerts on error rates and latency p99. *This matters because production systems are only as reliable as their observability; you cannot fix what you cannot measure.*

4. **Implement a circuit breaker pattern for the ML scorer.** Use a library like `pybreaker` to detect when the toxicity model is failing or timing out, and fall back to a lightweight regex-based heuristic. Track circuit state in Redis so all workers share the same failure awareness. *This matters because ML service dependencies are the #1 source of cascading failures in content moderation systems, and knowing how to degrade gracefully is what separates senior engineers from mid-level ones.*

5. **Add A/B testing for policy versions.** Store multiple policy configurations and randomly assign users to different versions. Log which version made each decision and track outcomes (false positive rate, user appeal rate). *This matters because policy iteration without experimentation is guesswork; this demonstrates you understand that safety systems require empirical validation, not just editorial decisions.*

6. **Implement batch adversarial testing with a red-team dataset.** Use a curated dataset of adversarial prompts (jailbreaks, encoded hate speech, obfuscated PII) to continuously evaluate model performance. Automate regression testing so that every model update is scored against the same benchmark. *This matters because safety systems degrade silently as adversaries adapt; continuous adversarial evaluation is the only way to ensure the system does not become a liability over time.*

## Key Takeaways

- `safe` demonstrates that you can architect a multi-stage pipeline with independent, replaceable components — the same pattern used in production trust-and-safety systems at scale.
- The separation of the policy engine from the detection scorers is the architectural centerpiece: it lets policy evolve without code deploys and detectors evolve without touching business logic.
- Real code, real dependencies, and real failure modes (model timeouts, rate limit exhaustion, database errors) make this project credible in a way that tutorial projects are not.
- The extension roadmap maps directly to senior-level concepts: horizontal scaling, circuit breakers, observability, A/B testing, and adversarial robustness.
- Every decision the system makes is audited, which mirrors the compliance requirements of any platform that processes user-generated content.
